# 第四章 硬件平台与接口实现

本章描述自动激光 PDH 锁定系统的硬件平台构成与各级接口设计，依次介绍以 Xilinx Kintex UltraScale FPGA 为核心的总体方案、模数/数模转换与时钟分发架构，以及上位机通信链路、片内自定义总线协议和器件配置接口三个层次的接口设计。

## 4.1 总体硬件方案

### 4.1.1 设计约束与方案选择

全数字 PDH 锁定系统的硬件设计受三项基本约束支配。

其一是**环路延迟约束**。如第二章 2.3 节所述，闭环系统的相位裕度直接受环路延迟 $\tau$ 制约，附加相移为 $\Delta\phi = -\omega\tau$。数字系统的延迟来自 ADC 转换、FPGA 内部流水线、DAC 建立三个环节，其中 FPGA 内部处理延迟与时钟频率成反比。因此系统时钟频率应尽可能高，且信号处理链路的流水线级数应尽可能少。

其二是**量化噪声约束**。误差信号的检测精度受 ADC 有效位数限制。理想 $N$ 位量化器的信噪比上限为

$$
\mathrm{SNR}_{\max} = 6.02N + 1.76 \ \mathrm{dB}
$$

该式给出噪声本底的理论下界，实际系统还需考虑孔径抖动、参考电压噪声与 FPGA 内部定点截断的贡献。

其三是**可重构性约束**。实验平台需要在不重新综合布线的前提下改变信号处理拓扑，这要求 FPGA 内部预先实例化全部功能模块，并通过可配置的互联网络连接，而非按固定链路硬连线。这一约束直接导出了第七章 7.1 节的信号路由矩阵设计。

基于上述约束，系统选用 Xilinx Kintex UltraScale 系列 FPGA 作为主控单元。该系列在逻辑资源、DSP48 硬核乘法器数量与高速串行接口能力之间取得平衡，适合承载多路并行的定点信号处理链路。系统时钟频率设定为 250 MHz，定义于 `packages/mypak.vhdl`：

```vhdl
constant clk_freq : integer := 250_000_000; -- Clock frequency in Hz.
```

系统内部数据通路统一采用 16 位有符号定点格式，定义为 `signal_array` 类型：

```vhdl
type signal_array is array(natural range <>) of std_logic_vector(15 downto 0);
```

该类型用于信号路由矩阵的输入输出端口以及顶层接口，是全系统信号互联的统一载体。16 位宽度与所选 ADC/DAC 的分辨率相匹配，在动态范围与资源占用之间取得折衷。

### 4.1.2 板卡与时钟架构

工程支持多种载板，通过不同的顶层封装文件区分：

| 载板 | 顶层封装文件 | 配置包 |
|------|-------------|--------|
| PZ-KU060-FHT | `wrapper_PZ-KU060-FHT.vhdl` | `packages/PZ_KU060_config.vhdl` |
| KU060 定制板 | `wrapper_KU060_custom.v` | `packages/KU060_custom_config.vhdl` |
| 通用板 | `wrapper.vhdl` | — |

顶层实体 `Top.vhdl`（871 行）为单时钟域设计，其 entity 仅声明一个 `clk` 端口，全部挂载在片内总线上的模块均由该时钟驱动。多时钟管理集中在封装层 `wrapper.vhdl` 中，由 MMCM（Mixed-Mode Clock Manager）完成。

MMCM 的输入参考时钟为 200 MHz，对应 `KU060_custom.xdc` 中的约束：

```tcl
create_clock -period 5.000 [get_ports sysclk_p]
```

MMCM 输出四路时钟，其中 `clk_out1` 为 250 MHz 系统主时钟（送入 `Top`），`clk_out2` 为 125 MHz DAC 时钟。`AN9767_adapter.vhdl` 中的注释明确了这一分频关系："AN9767 works at 125MHz, which is half of the system clock"。另两路 250 MHz 与 500 MHz 输出在代码中已实例化 BUFGCE 缓冲，但当前版本未见下游使用。

四路 BUFGCE 的时钟使能端均连接至 `sys_clk_locked`，在 MMCM 未锁定期间门控输出，避免未稳定时钟进入逻辑。MMCM 支持内部/外部参考切换，由 `sys_mmcm_sel` 信号选择。值得注意的是，切换控制器 `sys_mmcm_sel_ctrl` 与按键去抖模块 `debouncer` 均运行在 MMCM 之前的时钟域上，源码中有明确注释说明"Don't use clock from MMCM"——若控制器本身依赖被切换的时钟，切换瞬间将失去时序基准。

### 4.1.3 模数/数模转换架构

系统通过 FMC 接口支持多种 ADC/DAC 子卡，各子卡由独立的适配器模块（adapter）对接到统一的内部接口。`io management/` 目录下的适配器清单如下：

| 适配器文件 | 功能 |
|-----------|------|
| `FH8052_adapter.vhdl` | ADC 子卡适配 |
| `FH9767D_adapter.vhdl` | ADC 子卡适配 |
| `FL9613_adapter.vhdl` | ADC/DAC 子卡适配（16 位数据端口） |
| `FL9627_adapter.vhdl` | DAC 子卡适配 |
| `FL9781_adapter.vhdl` | ADC 子卡适配 |
| `FL1010_adapter.vhdl` | ADC 子卡适配 |
| `AN9767_adapter.vhdl` | DAC 子卡适配（125 MHz） |
| `ADDC/board_ku060_adda_top.v` | ADDC 高速 ADC/DAC 板 |

> 【待补充】上表各子卡的分辨率与采样率指标。代码中的适配器仅实现信号映射与 FIFO 逻辑，未在注释中标注器件的位数与采样率。`FL9613_adapter.vhdl` 的数据端口为 16 位（`adc_a_data` 至 `adc_d_data`，各 `std_logic_vector(15 downto 0)`），可推知该子卡为 16 位四通道，但采样率需查阅器件手册确认后填入。

适配器的典型职责由 `FL9613_adapter.vhdl` 的文件头注释概括："Maps input data, output clock and spi signals to the universal LPC interface. Contains FIFO logic."——即将子卡特定的引脚映射到统一的 LPC（Low Pin Count）FMC 接口，并处理跨时钟域的 FIFO 缓冲。

高速射频转换链路的核心器件由 `python control/chips.py` 中的 SPI 初始化例程配置，包括：

- **AD9680**——高速 ADC，初始化函数 `init_AD9680(spi, port, chip)`，配置完成后读取寄存器 `0x056F` 校验锁定状态，未锁定则抛出异常；
- **AD9152**——高速 DAC，初始化函数 `init_AD9152(spi, port, chip)`，校验寄存器 `0x0281`；
- **AD9528**——时钟分发与抖动清理 PLL，初始化函数 `init_AD9528(spi, port, chip)`，校验寄存器 `0x0508`，并可检测外部参考是否存在。

这三类器件的寄存器初始化序列同时以查找表形式固化在 `packages/PZ_KU060_config.vhdl` 中（`init_lut`，共 161 项），由 FPGA 内部的 SPI 任务序列器在上电时自动执行，无需上位机干预。该文件中另有 `query_lut`（3 项）用于周期性查询器件状态，查询结果经 `query_result` 输出至面板指示灯——`wrapper.vhdl:835` 的注释说明 `panel_led_2` 用于指示 AD9680 是否正常运行。

时钟分发器件 AD9528 的抖动性能直接影响 ADC 的有效位数。采样时钟的抖动 $\sigma_t$ 在输入信号频率 $f_{in}$ 处引入的信噪比上限为

$$
\mathrm{SNR}_{\mathrm{jitter}} = -20\log_{10}(2\pi f_{in}\sigma_t)
$$

当该项与量化噪声可比时，将成为系统噪声本底的主导因素。

> 【待补充】AD9528 的实测抖动指标与由此推算的 ADC 有效位数上限。需查阅器件手册典型值并结合实测相位噪声谱确认。

## 4.2 通信接口设计

系统的接口设计分为三个层次：上位机与 FPGA 之间的 UART 链路、FPGA 片内连接各功能模块的自定义总线、以及 FPGA 对板上射频器件的 SPI 配置接口。三者构成从 Python 脚本到器件寄存器的完整控制通路。

### 4.2.1 上位机通信链路

上位机与 FPGA 之间采用 UART 串行链路，波特率定义于 `packages/mypak.vhdl`：

```vhdl
constant baudrate : integer := 115200; -- Baudrate for the UART.
```

该文件中另有一条被注释掉的 3 906 250 波特配置，注释标明"Only use in simulation"——仿真时提高波特率可缩短验证周期。

选择 UART 而非 PCIe 或以太网作为控制链路，是基于控制与数据两类业务的分离考虑：参数配置属于低频、小数据量、强可靠性需求的业务，UART 的实现复杂度最低且时序确定；而大数据量的波形回传则由独立的以太网通路承担（`modules/waveform_storage_upload/`，含 DDR4 缓存与完整 MAC 协议栈）。两条通路互不干扰。

FPGA 侧的 UART 收发由 `uart_tx.vhdl` 与 `uart_rx.vhdl` 实现，命令解析由 `central_control.vhdl`（829 行）承担。该模块是一个状态机，负责从串行字节流中识别命令帧、解析字段、驱动片内总线，并组织响应回传。

上位机侧的驱动封装为 `python control/uart.py` 中的 `MySerial` 类，继承自 pyserial 的 `Serial`。其核心方法 `post()` 采用回显校验机制：发送命令后读回 FPGA 的回显并与原始命令比对，不一致则重发。这一机制以牺牲吞吐量换取链路可靠性，对参数配置类业务是合适的权衡。

### 4.2.2 板级总线协议设计

片内总线是本系统架构的核心。为使 34 个功能模块（`module_count = 34`）以统一方式接受配置，系统设计了一套自定义的并行总线协议，其信号定义集中在 `packages/mypak.vhdl`：

| 常量 | 位宽 | 含义 |
|------|------|------|
| `dbus_w` | 32 | 数据总线宽度 |
| `abus_w` | 7 | 地址总线宽度，决定每模块参数 RAM 容量为 $2^7=128$ 字 |
| `mbus_w` | 6 | 模块选择总线宽度，最多寻址 $2^6=64$ 个模块 |
| `cbus_w` | 5 | 控制总线宽度 |
| `rdbus_w` | 32 | 响应数据总线宽度 |
| `rsbus_w` | 3 | 响应状态总线宽度 |

由此导出单模块参数存储容量上限：

```vhdl
constant core_param_size : integer := 2 ** abus_w * dbus_w; -- = 4096 bit
```

即每个模块最多可拥有 4096 位参数空间。实际各模块按需取用：PDH 状态机与 PID 控制器使用 256 位（`core_param_in : in std_logic_vector(255 downto 0)`），信号路由矩阵使用 1024 位，FIR 滤波器因需存储 64 个 24 位系数而使用全部 4096 位。

总线采用集中式主从结构。`central_control.vhdl` 作为唯一主设备，各模块通过专属的 `bus_handler.vhdl` 实例接入。模块地址以常量形式静态分配，例如：

```vhdl
constant BUS_ROUT_ADDR : ... := to_unsigned(1, mbus_w);  -- 信号路由矩阵
constant BUS_TRIG_ADDR : ... := to_unsigned(2, mbus_w);  -- 三角函数运算器
constant BUS_ACCM_ADDR : ... := to_unsigned(3, mbus_w);  -- 累加器
constant BUS_PIDC_ADDR : ... := to_unsigned(6, mbus_w);  -- PID 控制器
```

地址 0 保留表示"无模块"，响应总线类型 `rdbus_type` 与 `rsbus_type` 的索引范围均为 `0 to module_count`，其中 0 号位置不对应实际模块。响应数据经 `response_mux.vhdl` 多路选择后回传主设备。

**命令编码方案**定义于 `packages/bus_protocol.vhdl`。控制总线的 5 位命令字采用分层编码：高 2 位标识命令类型，低 3 位标识具体动作。这一编码方式使从设备可先按高 2 位快速分支，再解析具体操作，降低解码逻辑深度。

| 类型头 | 编码 | 命令 | 低 3 位 | 功能 |
|--------|------|------|---------|------|
| `CONTROL_HEAD` | `00` | `SET_CORE` | `010` | 模块内核复位置 0 |
| | | `RST_CORE` | `011` | 模块内核复位置 1 |
| | | `SET_RAM` | `100` | 参数 RAM 复位置 0 |
| | | `RST_RAM` | `101` | 参数 RAM 复位置 1 |
| `WRITE_HEAD` | `01` | `WRITE` | `000` | 写入并立即生效 |
| | | `WRITE_HOLD` | `001` | 写入但暂不生效 |
| | | `WRITE_MASK` | `100` | 带掩码写入并立即生效 |
| | | `WRITE_MASK_HOLD` | `101` | 带掩码写入但暂不生效 |
| `READ_HEAD` | `10` | `READ` | `000` | 读取指定地址 |
| `MISC_HEAD` | `11` | — | — | 由各模块的总线处理器自定义 |

响应状态总线有两个取值：`ROGER`（`001`）表示命令已执行，`ERROR`（`111`）表示执行失败，错误详情经响应数据总线返回。

协议中 `HOLD` 变体的设计值得专门说明。许多模块的参数宽度超过 32 位数据总线——例如 PID 控制器的积分限幅 `limit_integral` 为 48 位，累加器的频率字 `delta` 为 64 位。若分多次写入且每次立即生效，参数将在中间状态下短暂作用于运行中的控制环路，可能造成输出跳变甚至失锁。`WRITE_HOLD` 命令将数据写入影子寄存器而不提交，待最后一条 `WRITE` 命令到达时一并生效，从而实现**多寄存器参数的原子化更新**。`module_pid_controller.vhdl` 中 `wen`（写使能）与 `wval`（写生效）两个信号的分离正是这一机制在模块侧的落地。

`WRITE_MASK` 变体用于位域级更新：同一地址内可能打包多个逻辑参数（如 PDH 状态机将 2 位的 `pc_cmd` 放在地址 0x00 的最低两位），掩码写入使上位机可只修改目标位域而不扰动同址的其他参数。该命令需占用两个总线周期，第一周期传数据、第二周期传掩码。

### 4.2.3 器件配置接口

板上射频器件（AD9680、AD9152、AD9528 等）通过 SPI 接口配置。FPGA 侧由 `spi_trx.vhdl` 实现物理层收发，`spi_task_control.vhdl` 实现任务序列化。SPI 时钟频率定义为

```vhdl
constant spi_clk_freq : integer := 1_000_000; -- SPI clock frequency in Hz.
```

即 1 MHz，远低于系统时钟，由计数器分频产生。

SPI 片选通过地址常量映射到 FMC 端口与芯片编号的组合，例如：

```vhdl
constant SPI_P4C3_ADDR : integer := 14; -- Address of chip 3 on FMC Port 4.
constant SPI_P4C4_ADDR : integer := 15; -- Address of chip 4 on FMC Port 4.
```

这种编址方式使同一套 SPI 控制逻辑可服务于多个 FMC 端口上的多片器件。

配置流程存在两条并行通路，分别服务于不同场景：

1. **上电自动配置**：初始化序列以查找表形式固化在板卡配置包中（如 `PZ_KU060_config.vhdl` 的 `init_lut`，161 项），由 `spi_task_control.vhdl` 在复位释放后自动遍历执行。该通路不依赖上位机，保证 FPGA 单板上电即可进入可用状态。配置包中对 AD9528 有一条特殊处理——向不存在的地址写入以制造延时（源码注释："write to non-existing address to simulate delay"），这是因 PLL 锁定需要建立时间，而查找表机制本身不支持显式等待指令。

2. **上位机按需配置**：由 `python control/chips.py` 中的 `init_AD9680` / `init_AD9152` / `init_AD9528` 等函数经 SPI 通路下发，并读回状态寄存器校验锁定。`python control/boards.py` 将这些函数组织为板级初始化流程。该通路用于调试阶段的参数迭代与故障诊断。

两条通路共用同一套 SPI 硬件逻辑，区别仅在于命令来源。上位机侧的 SPI 访问封装在 `python control/spi.py` 中，与 `bus.py` 并列构成硬件抽象层的两个分支，详见第九章 9.1 节。

## 4.3 本章小结

本章介绍了系统的硬件架构与接口设计。硬件平台以 Xilinx Kintex UltraScale FPGA 为核心，运行于 250 MHz 系统时钟，内部数据通路统一为 16 位有符号定点格式；通过 FMC 接口支持多种 ADC/DAC 子卡，高速射频链路由 AD9680 ADC、AD9152 DAC 与 AD9528 时钟分发器件构成，经 SPI 接口配置并校验锁定状态。接口设计分三个层次：UART 承担低速高可靠的参数配置业务并以回显校验保证链路可靠性；片内自定义并行总线以 32 位数据、7 位地址、6 位模块选择的编址方案连接 34 个功能模块，其分层命令编码与 `HOLD` 机制分别降低了解码复杂度、实现了超宽参数的原子化更新；SPI 接口则以固化查找表与上位机下发两条通路完成板上器件配置。本章确立的总线协议与数据格式是第五章各功能模块设计的共同基础。
