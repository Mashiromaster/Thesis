# 第六章 实验应用的平台实现

前几章分别给出了平台的设计方法（第三章）与运算模块的实现（第五章）。本章转向验证性的问题：**这一平台能否真正承载形态不同的实验？**

回答这一问题需要具体的案例。本章给出两类已在平台上实现的实验应用：激光 PDH 锁定与双光梳自校准本振锁定。选择这两者并非因为它们是平台唯一的用途，而是因为它们在控制结构上具有代表性的差异——前者处理幅度量、须主动扫描以捕获共振，后者处理相位量、须先测频再校准本振。二者对平台提出了不同的要求，因而共同构成了对平台通用性的检验。

本章的组织方式是：先建立"实验应用"在平台上的一般表述（6.1 节），再依次展开两个案例（6.2、6.3 节），最后对比二者以归纳平台通用性的来源与边界（6.4 节）。

## 6.1 实验应用在平台上的表述

### 6.1.1 应用的三要素

在本平台上，一个实验应用由三部分完全确定：

| 要素 | 内容 | 配置手段 |
|------|------|---------|
| 拓扑 | 哪些运算模块参与、如何连接 | 路由矩阵的配置字 |
| 参数 | 各模块的增益、系数、阈值 | 总线写入参数 RAM |
| 自动化逻辑 | 状态推进与模块使能的时序决策 | 应用层状态机 |

前两者是数据，第三者是逻辑。这一划分的实际意义是：**凡能以既有模块的重新连接与参数调整表达的实验，都无需改动硬件**；只有当实验需要新的自动化决策流程时，才需要在应用层增加一个状态机模块并重新综合。

两个案例恰好分处这一界线的两侧：PDH 锁定与双梳锁定各自需要专属的状态机（`pdh_state_machine` 与 `SCALO_state_machine`），因而都包含第三要素；但二者的运算层与互联层完全共用，没有为任一应用增加专用的运算模块。

### 6.1.2 状态机作为应用层的载体

应用层状态机的职责不是参与信号运算，而是**决策**：判断当前实验处于哪个阶段，据此门控运算模块的工作状态。其与运算层的交互仅通过两类信号——从数据路由矩阵读入用于判决的信号，向布尔路由矩阵输出复位或使能信号。

这一约定使应用层与运算层保持解耦：状态机不知道被它复位的是哪一个具体的 PID 实例（那由布尔矩阵的配置决定），运算模块也不知道自己的复位来自哪个状态机。第三章 3.2.3 节的自动复位契约正是为此设计。其结果是**同一个状态机可以控制不同的模块组合**，而无需修改状态机本身。

## 6.2 应用一：激光 PDH 锁定

本节是对第二章 PDH 原理的工程落实。其核心模块 `modules/pdh_state_machine/pdh_state_machine.vhdl`（305 行）将"扫描—判定—锁定"的决策逻辑完全置于硬件内部，响应时间为时钟周期量级，而非依赖上位机轮询的毫秒量级。

### 6.2.1 物理约束决定的设计要求

第二章 2.1.4 节给出了一个关键推论：PDH 鉴频斜率 $D = -8\sqrt{P_cP_s}/\delta\nu$ 与腔线宽成反比，因此高灵敏度必然伴随窄捕获范围——线性区仅约一个腔线宽。对于精细度 $10^4$ 量级的参考腔，这意味着误差信号的有效区间远窄于激光的自由运转漂移范围。

由此导出两项设计要求。其一，**环路无法自行捕获**，必须先主动扫描激光频率（或腔长）以寻找共振，再在越过共振的瞬间闭合环路。其二，**捕获的时机判断必须快**：扫描经过共振线性区的时间很短，若判断与闭环动作存在毫秒级的软件延迟，窗口早已错过。这两点共同决定了自动锁定逻辑必须下沉至硬件。

### 6.2.2 接口与状态划分

模块接口为：

```vhdl
port (
    clk, rst        : in  std_logic;
    core_param_in   : in  std_logic_vector(255 downto 0);
    sig_in          : in  std_logic_vector(15 downto 0);  -- 用于有效性判定的输入信号
    pid_enable      : out std_logic;  -- PID 控制器使能
    mixer_enable    : out std_logic;  -- 混频器使能
    sawtooth_enable : out std_logic;  -- 扫描锯齿波使能
    saw_input       : in  std_logic_vector(15 downto 0)
);
```

三路使能输出分别门控 PID、混频器与锯齿波发生器，构成状态机对信号链路的控制手段。需注意这三个信号为**低有效**语义——锁定态下置 '0'。

状态定义为八个状态：

```vhdl
type state_type is (IDLE, AUTO_AMP, AUTO_TIME, AUTO_WAIT,
                    AUTO_SCANNING, SCANNING, AUTO_LOCKING, LOCKING);
```

> **与研究计划的差异说明**：原研究计划将状态机描述为"扫描（Scan）→ 判定（Judge）→ 锁定（Lock）→ 保持（Hold）"四态流程。实际实现为八态，其中增加的 `AUTO_AMP`、`AUTO_TIME`、`AUTO_WAIT` 三态构成自动参数标定阶段，而手动与自动流程各有独立的扫描/锁定状态。实现较原计划更为完整，本节按代码实况描述。

八个状态构成两条并行的分支链路：

**手动链路**（由上位机指定阈值）：
$$
\texttt{IDLE} \xrightarrow{\texttt{pc\_cmd}=01} \texttt{SCANNING} \xrightarrow{\text{信号持续低于扫描阈值}} \texttt{LOCKING} \xrightarrow{\text{信号持续高于锁定阈值}} \texttt{IDLE}
$$

**自动链路**（硬件自行标定阈值）：
$$
\texttt{IDLE} \xrightarrow{\texttt{pc\_cmd}=10} \texttt{AUTO\_WAIT} \to \texttt{AUTO\_AMP} \to \texttt{AUTO\_TIME} \to \texttt{AUTO\_SCANNING} \to \texttt{AUTO\_LOCKING}
$$

状态跳转由两位命令字 `pc_cmd`（来自参数总线地址 0x00 的最低两位）与锯齿波回扫沿 `sawtooth_jump` 共同驱动。

### 6.2.3 锯齿波回扫沿检测

自动标定的各阶段均以扫描周期为单位推进，因此需要可靠的周期边界标志。源码采用如下判据：

```vhdl
if ((saw_input_signed(15) XOR saw_input_signed(14)) = '1'
    and saw_input_signed(15) /= saw_input_prev(15)) then
    sawtooth_jump <= '1';
```

该条件同时要求符号位与次高位相异（即信号处于量程两端的回扫区）、且符号位发生翻转。相比单纯的符号跳变检测，附加的幅度条件可抑制信号在零点附近的噪声抖动误触发。

### 6.2.4 自动幅度标定与阈值计算

这是本模块的算法核心，也是本平台自动化能力的集中体现。

**`AUTO_AMP` 态**在一个完整扫描周期内追踪输入信号的极值：

```vhdl
if sig_in_buf < min_sig_in then min_sig_in <= sig_in_buf; end if;
if sig_in_buf > max_sig_in then max_sig_in <= sig_in_buf; end if;
```

两个极值寄存器在进入该态时被初始化为相反的极端值（`min_sig_in` 置为最大正值、`max_sig_in` 置为最小负值），以保证首个采样即可正确更新。

**阈值计算**由组合逻辑完成，分三级流水：

```vhdl
diff_sig_in_buf <= resize(max_sig_in, 17) - resize(min_sig_in, 17);     -- Q17.0 峰峰值
scaled_scan_sig_in_buf <= diff_sig_in * coef_scan;                      -- Q18.15
auto_threshold_signal_scanning_buf <= min_sig_in + scaled_scan_sig_in(30 downto 15); -- Q16.0
```

即阈值按下式计算：

$$
V_{th} = V_{min} + (V_{max} - V_{min}) \cdot c
$$

其中系数 $c$（`coef_scan` 与 `coef_lock`）为 Q1.15 格式的 16 位有符号数，由上位机配置。扫描阈值与锁定阈值使用各自独立的系数，因而可设置不同的判定水平——通常锁定判据应比扫描判据更严格，以避免在共振峰边缘误判为已锁定。

这一相对阈值方案的优势在于**自适应于信号幅度**。激光功率漂移、光路耦合效率变化、探测器增益差异都会改变误差信号的绝对幅度，固定阈值在此情况下需频繁重新标定；而相对阈值仅依赖峰峰值的比例，对幅度变化免疫。这一点对长时间无人值守运行尤为重要。

**`AUTO_TIME` 态**进一步自动标定时间门限。该态测量信号持续低于扫描阈值的时长 `time_able`，并据此导出两个时间参数：

```vhdl
if time_able > min_AUTO_TIME then
    measurement_done <= '1';
    auto_time_duration_scanning <= '0' & time_able(31 downto 1);  -- ×0.5
    auto_time_duration_locking  <= time_able(29 downto 0) & "00"; -- ×4
```

扫描判定时长取测得值的一半，锁定判定时长取四倍——两者均以移位实现，无需乘法器。取半的用意是使扫描阶段的判定比实测的共振峰宽度更宽松以确保捕获，取四倍则使锁定阶段的失锁判定更为迟缓以避免瞬态扰动引发误判。

另设下限门限防止噪声误触发：

```vhdl
constant min_AUTO_TIME : unsigned(15 downto 0) := to_unsigned(500, 16);
```

即过阈时长须超过 500 个时钟周期（250 MHz 下为 2 μs）才被认可为有效的共振峰。

### 6.2.5 判定与锁定交接

**`AUTO_SCANNING` 态**执行持续时间判定：信号低于阈值时计数器累加，达到 `auto_time_duration_scanning` 则转入锁定；信号一旦高于阈值即将计数器清零。这一"连续满足"而非"瞬时满足"的判据有效抑制了噪声尖峰造成的误锁定。

**`AUTO_LOCKING` 态**置 `pid_enable <= '0'`、`mixer_enable <= '0'`（低有效，即启用 PID 与混频器），同时 `sawtooth_enable <= '1'` 停止扫描，系统进入闭环锁定。

此处的交接细节值得强调：状态机本身不产生扫描斜坡，而是通过布尔路由矩阵门控相位累加器的暂停输入与 PID 的自动复位输入。在同一个时钟沿上冻结斜坡并释放 PID，使累加器保持捕获时刻的偏置、由 PID 接管后续校正。整个交接在硬件内部单周期完成，不存在软件轮询带来的不确定延迟——这正是 6.2.1 节第二项设计要求的实现。

### 6.2.6 关于自动重锁机制

研究计划中列有"自动重新锁定机制（Auto-relogin）"一项。经核查代码，**该功能当前尚未实现**。`AUTO_LOCKING` 态在检测到信号不再满足锁定条件时，仅执行计数器清零：

```vhdl
when AUTO_LOCKING =>
    ...
    -- 失锁时仅 time_able <= (others => '0')，不发生状态跳转
```

离开该状态的唯一路径是 `pc_cmd` 被上位机改写为 `"00"` 或 `"11"` 而回到 `IDLE`。手动链路的 `LOCKING` 态同理。因此当前的失锁恢复仍需上位机介入，不属于硬件自主重锁。

实现硬件自动重锁在结构上并不困难——只需在 `AUTO_LOCKING` 态增加一条指向 `AUTO_SCANNING` 的跳转，条件为失锁持续时间超过 `auto_time_duration_locking`。由于阈值与时间参数已在自动标定阶段求得并保存，重锁无需重新标定即可直接复用。该项列为第十章的改进方向。

### 6.2.7 参数地址映射与平台集成

模块的可配置参数经 `parameter_ram_256` 映射如下：

| 地址 | 位段 | 参数 | 类型 |
|------|------|------|------|
| 0x00 | `[1:0]` | `pc_cmd` | 2 位命令字 |
| 0x01 | `[47:32]` | `threshold_signal_locking` | signed 16 |
| 0x02 | `[79:64]` | `threshold_signal_scanning` | signed 16 |
| 0x03 | `[127:96]` | `time_duration_scanning` | unsigned 32 |
| 0x04 | `[159:128]` | `time_duration_locking` | unsigned 32 |
| 0x05 | `[175:160]` | `coef_scan` | signed 16, Q1.15 |
| 0x06 | `[207:192]` | `coef_lock` | signed 16, Q1.15 |

该模块在片内总线上的地址为 26（`BUS_PDHS_ADDR`）。顶层 `Top.vhdl` 中的连接关系为：`sig_in` 接 `sig_bank_out(37)`，`saw_input` 接 `sig_bank_out(38)`，三路使能输出接 `ctrl_bank_in(2..4)`——即状态机的输入输出同样经过信号路由矩阵，其连接关系亦可由上位机动态配置。

这一点体现了第三章分层结构的价值：状态机并未被硬连线到特定的 PID 或混频器实例。实验者可以在运行时改变"由哪一路信号触发判决"、"复位哪一个 PID"，而无需修改状态机代码。

### 6.2.8 典型拓扑

一个完整的 PDH 锁定构型涉及五个模块与九条连线，其数据流为：

$$
\text{累加器} \to \text{CORDIC} \xrightarrow{\cos} \text{混频器} \xrightarrow{\text{解调}} \text{PID} \to \text{累加器（反馈）}
$$

其中累加器产生扫描斜坡与调制参考相位，CORDIC 将相位转为正交本振，混频器以余弦分量解调探测器信号得到误差信号，PID 计算校正量回授至累加器。PDH 状态机则并联于该链路之外，读入判决信号与斜坡信号，输出三路使能。

该拓扑的具体连线清单已固化在上位机的自动化脚本与智能体知识库中（第七章 7.3 节、第八章 8.4.2 节），使其可一键复现。

## 6.3 应用二：双光梳自校准本振锁定

本节给出第二个应用案例。其意义在于：该应用与 PDH 在控制对象、信号类型与自动化策略上均不相同，却完全复用了同一套运算层与互联层。

### 6.3.1 应用背景与控制目标

光学频率梳的输出可由两个射频参量完全描述：重复频率 $f_r$ 与载波包络偏移频率 $f_{ceo}$，第 $n$ 根梳齿的频率为

$$
\nu_n = n f_r + f_{ceo}
$$

双光梳系统使用两台梳源，其拍频信号携带二者的 $f_r$ 之差与 $f_{ceo}$ 之差。欲使两台梳源保持相干，须将这两个差频分别锁定。`Top.vhdl` 的文件头注释明确说明了系统的这一设计目标："The system is designed to lock the fr diff and fceo diff in a dual comb system."

与 PDH 的关键差异在于**被控量的性质**。PDH 中误差信号是一个幅度量（解调后的电压），其零点对应共振；而此处被控量是两个信号之间的**相位差**，须先由相位检测得到，且相位量具有模 $2\pi$ 的周期性。第二章 2.2.3 节所述的 CORDIC 向量模式与相位解卷绕模块正是为处理这类信号而设。

### 6.3.2 自校准本振的必要性

锁相检测要求本振频率与待测信号频率一致。但在双梳系统中，拍频的频率取决于两台梳源的实际状态，开机时并不精确已知，且会随环境漂移。若本振频率与信号频率存在偏差 $\Delta f$，则检测到的相位将以 $2\pi\Delta f$ 的速率持续累积，表现为相位的线性斜坡而非围绕定值的波动——此时环路无法锁定。

传统做法是人工测量拍频并手动设置本振频率。`SCALO_state_machine`（SCALO 即 self-calibrating local oscillator，自校准本振）将这一过程自动化：**先测量相位的漂移速率以推算频率偏差，再把该偏差补偿进本振的相位增量，然后才启动 PID**。

其原理可由相位与频率的关系直接给出。本振与信号的瞬时相位差为

$$
\phi(t) = 2\pi \Delta f \, t + \phi_0
$$

对其求导即得频率偏差：

$$
\Delta f = \frac{1}{2\pi}\frac{d\phi}{dt}
$$

在离散时间下，相位差分 $\phi[n] - \phi[n-1]$ 正比于 $\Delta f$。因此只需测得相位的平均差分，即可求出应补偿的本振频率增量。

### 6.3.3 实现结构

模块接口相当简洁（`modules/SCALO_state_machine/SCALO_state_machine.vhdl`，204 行）：

```vhdl
port(
    clk             :   in  std_logic;
    rst             :   in  std_logic;
    core_param_in   :   in  std_logic_vector(63 downto 0);
    -- data flow ports
    phase_in        :   in  std_logic_vector(15 downto 0);
    phase_out       :   out std_logic_vector(15 downto 0);
    -- control ports
    pid_reset_out   :   out std_logic
);
```

输入为来自反三角函数（atan2）模块的相位，输出为本振的相位偏置修正值与一路 PID 复位控制。注意其端口构成完全遵循第三章 3.2.1 节的范式——`core_param_in` 承载参数、数据端口承载相位、控制端口输出复位。

**相位差分与滑动窗平均。** 核心运算分两步。首先计算相邻采样的相位差：

```vhdl
phase_in_buf_1 <= phase_in_buf;
phase_diff <= phase_in_buf_1 - phase_in_buf;
```

源码注释指出了符号约定："positive diff indicates LO freq larger than sig so requires a negative bias"——差分为正表示本振频率高于信号，需施加负向偏置。

随后以一个 256 级移位寄存器链构成滑动窗平均器：

```vhdl
buf_gen : for i in 0 to 254 generate
    ...
    phase_diff_buf(i + 1) <= phase_diff_buf(i);
end generate;
...
sum <= sum - (符号扩展(phase_diff_buf(255))) + (符号扩展(phase_diff_buf(0)));
```

该结构以**增量更新**计算窗口和：每周期减去移出窗口的最旧样本、加上最新样本，因而无论窗口多长都只需一次加法与一次减法，代价是 256 级寄存器的面积。这是一种典型的以空间换时间的流水线设计——若改为每周期重新累加 256 个样本，无论如何流水化都无法在 250 MHz 下闭合时序。

窗口长度 256 的选择在于噪声抑制：相位差分对噪声极为敏感（差分运算放大高频噪声，见第二章 2.3.1 节关于微分项的讨论），而平均 256 个样本可将白噪声的标准差降低 16 倍。最终取 `sum(23 downto 8)` 即相当于除以 256 得到平均值。

**三态流程。** 状态机仅三个状态：

```vhdl
type state_type is (s_IDLE, s_CALIBRATING, s_LOCKING);
```

其转移关系为：

$$
\texttt{s\_IDLE} \xrightarrow{\texttt{lock} \text{ 上升沿}} \texttt{s\_CALIBRATING} \xrightarrow{\text{计数达 128}} \texttt{s\_LOCKING} \xrightarrow{\texttt{lock} \text{ 下降沿}} \texttt{s\_IDLE}
$$

`s_CALIBRATING` 态的驻留时间由常量固定：

```vhdl
constant calibrating_time : unsigned(7 downto 0) := x"80"; -- 128 周期
```

源码注释说明了该值的用意："Enough time for calibrated freq to propagate"——即等待校准后的频率值在流水线中传播到位。在 250 MHz 下 128 周期约 512 ns。

**偏置的累加与清零。** 本振偏置在 `lock` 上升沿时被更新：

```vhdl
if clear_rising = '1' then
    bias <= (others => '0');
elsif lock_rising = '1' then
    bias <= bias + sum(23 downto 8);
end if;
```

注意这是**累加**而非赋值。其含义是每次触发锁定时，将当前测得的频率偏差增量叠加到已有偏置上——因此反复触发可逐步收敛至精确值，而 `clear` 命令则将偏置复位为零以重新开始。

**PID 的门控。** 输出逻辑仅一行：

```vhdl
pid_reset_out <= '0' when state = s_LOCKING else '1';
```

即仅在 `s_LOCKING` 态释放 PID 复位。这保证了 PID 只在本振已校准完毕后才开始积分，避免在校准阶段累积由频率失配引起的虚假误差——与 PDH 状态机在扫描阶段保持 PID 复位的用意完全一致。

### 6.3.4 与 PDH 应用的结构类比

尽管物理场景不同，两个应用在控制结构上呈现出清晰的对应关系：

| 环节 | PDH 锁定 | 双梳自校准本振锁定 |
|------|---------|------------------|
| 被控量 | 幅度量（解调电压） | 相位量（相位差） |
| 捕获前的未知量 | 共振位置、信号幅度 | 拍频频率 |
| 自动标定对象 | 幅度阈值、时间门限 | 本振频率偏置 |
| 标定方法 | 扫描一周期取极值 | 相位差分 + 256 点滑动平均 |
| 标定所需时间 | 一个扫描周期 | 128 周期（约 512 ns） |
| 交接动作 | 冻结斜坡 + 释放 PID | 补偿本振 + 释放 PID |
| 状态数 | 8 | 3 |

共同的模式是：**先以开环方式测量未知参量，再据测量结果配置环路，最后才闭合反馈**。这一"测量—配置—闭环"的三段式流程是两类实验自动化的共同骨架，差异仅在于被测量的物理量与测量方法。

平台对这一共性的支持体现在第三章 3.2.3 节的自动复位契约：两个状态机都通过同一机制门控 PID，而无需各自实现专属的使能通路。

## 6.4 平台通用性的来源与边界

### 6.4.1 通用性的三个来源

两个案例共用同一套硬件，其可能性来自三项机制，均在第三章确立：

**其一，运算模块的物理无关性。** PID 控制器不知道自己调节的是激光频率还是本振相位，混频器不知道自己解调的是 PDH 边带还是梳齿拍频。模块只实现数学变换，物理含义由实验者赋予。这使同一个模块可服务于不同应用。

**其二，互联的运行时可配。** 两个应用的拓扑差异（PDH 用混频器解调，双梳用 CORDIC 向量模式解相位）完全由路由矩阵的配置字表达，无需重新综合。切换应用的代价是数十次寄存器写入，即毫秒量级。

**其三，控制信号的可路由性。** 布尔矩阵使"哪个状态机复位哪个 PID"成为运行时可配的关系。这是两个状态机能够共存于同一比特流、并按需启用其一的前提。

### 6.4.2 边界与代价

需客观指出平台通用性的限度。

**新的自动化流程仍需重新综合。** 如 6.1.1 节所述，若实验需要一种既有状态机都无法表达的决策逻辑，须新增应用层模块并重新综合。平台降低的是拓扑调整的成本，而非逻辑开发的成本。第八章的代码生成工具针对的正是这一环节的样板代码负担。

**模块实例数构成硬上限。** 每类模块的实例数在综合时固定（如 PID 为 2 个实例），超出即无法实现。这使平台当前难以支持多路激光同时锁定，相关讨论见第十章。

**资源代价由全部应用共同承担。** 固化全部模块意味着即使当前只运行 PDH 实验，双梳应用所需的 CORDIC、解卷绕器与 SCALO 状态机仍占据芯片面积。这是通用性的直接代价，也是第三章 3.4.3 节所述平方增长问题的一部分。

### 6.4.3 对微纳光学实验的适用性讨论

本章的两个案例均属激光频率与相位的控制。就平台的架构而言，其适用范围不限于此——凡满足"误差信号可由 ADC 采集、校正量可由 DAC 输出、控制带宽在百千赫兹量级以内"的实验，原则上都可由现有模块的重新组合实现。第一章 1.1 节列举的微腔热锁定、光力学系统的模式冷却、调制转移光谱锁定等场景在控制结构上与本章案例同源。

但须强调这是**架构层面的推断，而非已验证的事实**。本文已实现并可报告的应用为本章两例；其他场景的适用性需待实际实验验证，相关讨论列入第十章的展望而不作为本文结论。这一界限的划分是必要的：平台的价值应由已实现的案例支撑，而非由未经检验的可能性支撑。

## 6.5 本章小结

本章以两个实验应用检验了平台的通用性。

在平台上，一个实验应用由拓扑、参数与自动化逻辑三要素确定，前两者是可运行时配置的数据，后者是需综合的逻辑。应用层状态机作为自动化逻辑的载体，仅通过数据矩阵读入判决信号、通过布尔矩阵输出门控信号，因而与运算层保持解耦。

**PDH 锁定应用**的设计要求直接源于物理约束：鉴频斜率与腔线宽成反比导致捕获范围极窄，环路无法自行捕获且捕获窗口短暂，故自动锁定逻辑必须下沉至硬件。其实现为八态状态机，含 `AUTO_AMP` 与 `AUTO_TIME` 两个自动标定态，按 $V_{th} = V_{min} + c(V_{max}-V_{min})$ 导出相对阈值，使系统对激光功率漂移与探测器增益差异免疫；时间门限以移位实现的 ×0.5 与 ×4 导出，无需乘法器。捕获瞬间在同一时钟沿冻结斜坡并释放 PID，交接过程无软件介入。当前的欠缺是失锁后的自主重锁尚未实现。

**双梳自校准本振锁定应用**处理的是相位量而非幅度量，其未知参量是拍频频率而非共振位置。`SCALO` 状态机以相位差分推算频率偏差 $\Delta f = \frac{1}{2\pi}\frac{d\phi}{dt}$，经 256 级移位寄存器构成的增量式滑动窗平均器抑制差分噪声，将结果累加至本振相位偏置，再释放 PID。其三态流程较 PDH 简洁，但遵循相同的"测量—配置—闭环"骨架。

两个应用在物理场景上迥异，却共用同一套运算层与互联层，没有为任一应用增加专用运算模块。这一事实构成了对平台通用性的实证。通用性来自三项机制：运算模块的物理无关性、互联的运行时可配、控制信号的可路由性。其边界同样明确：新的自动化流程仍需重新综合，模块实例数构成硬上限，且全部应用的资源代价由单一比特流共同承担。
